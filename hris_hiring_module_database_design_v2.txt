HRIS RECRUITMENT / HIRING MODULE
Database Design — MySQL / Laravel
Version: 2.0 (status master + offer letter + hiring stages)

Scope
-----
Hiring process only: jobs -> candidates/resumes -> applications -> stages -> interviews -> offers/offer letters -> joining.
Timesheet, leave, salary revisions, designation history and employee management are OUT of scope
(moved to a separate Employee module document).

General conventions
-------------------
- BIGINT UNSIGNED AUTO_INCREMENT primary key named id.
- InnoDB, utf8mb4 / utf8mb4_unicode_ci.
- created_at / updated_at on all tables; deleted_at only where noted.
- Files in private storage; DB stores the path only.
- Index every FK and commonly searched column.
- Laravel migrations are the source of truth. Create in a NEW development database.
- Delete rules: RESTRICT for history/transactional data, SET NULL for optional references. No broad CASCADE
  (CASCADE allowed only for pure child rows, e.g. candidate_skills, offer_salary_components).
- Passwords hashed by Laravel.
- Money columns always have a currency_code next to them.

=====================================================================
STATUS MASTER
=====================================================================
Every table that has a status uses status_id -> statuses.id instead of a TINYINT/VARCHAR status.
Statuses are grouped by `module`, so each table only allows statuses of its own module
(enforce in Laravel validation: Rule::exists('statuses','id')->where('module', '<module>')).

0. statuses
-----------
- id: BIGINT UNSIGNED, PK, AUTO_INCREMENT
- module: VARCHAR(50), NOT NULL (see module list below)
- code: VARCHAR(50), NOT NULL (machine value used in code, e.g. 'open', 'accepted')
- name: VARCHAR(100), NOT NULL (display label, e.g. 'Open', 'Offer Accepted')
- color: VARCHAR(20), NULL (badge colour, e.g. 'success', '#28a745')
- sort_order: SMALLINT UNSIGNED, NOT NULL, DEFAULT 0
- is_default: TINYINT(1), NOT NULL, DEFAULT 0 (default status for new records of this module)
- is_final: TINYINT(1), NOT NULL, DEFAULT 0 (terminal status; record can no longer change)
- is_active: TINYINT(1), NOT NULL, DEFAULT 1
- created_at, updated_at: TIMESTAMP, NULL
- UNIQUE (module, code)
- INDEX (module, is_active)
- Note: is_active is a plain flag here (the status table cannot reference itself).

Seed data (module -> codes)
---------------------------
general            : active, inactive
                     (used by roles, users, countries, practice_areas, clients, client_managers,
                      vendors, skills, hiring_stages, offer_letter_templates)
job                : draft, open, on_hold, closed, filled, cancelled
candidate          : active, blacklisted, placed, inactive
document           : pending_verification, verified, rejected
application        : active, on_hold, rejected, withdrawn, hired
interview          : scheduled, rescheduled, completed, cancelled, no_show
interview_result   : selected, rejected, on_hold, next_round
offer              : draft, pending_approval, approved, rejected, sent, accepted, declined,
                     revised, expired, withdrawn, joined, no_show
approval_action    : submitted, approved, rejected, cancelled

Rule: never hard-code status ids in code. Look up by (module, code), e.g.
Status::idFor('offer', 'accepted') — cache the lookup.

=====================================================================
HIRING FLOW
=====================================================================
1. Create job (status: draft -> open), assign recruiters/vendors, add skills.
2. Add candidate + upload resume (candidate_documents, document_type = resume).
3. Tag candidate to job -> job_applications (stage: Sourced, status: active). Log stage history.
4. Move through stages (Screening -> Client Submission -> L1 -> L2 -> HR). Every move = 1 history row.
5. Schedule interviews per round; panelists submit feedback; set result.
6. Selected -> create offer (draft) from template + salary components.
7. Approval (offer_approvals) -> approved -> generate PDF -> sent.
8. Candidate accepts/declines. Revision = new offers row, old row is_current = 0, status 'revised'.
9. On joining: offer status 'joined', application status 'hired', jobs.positions_filled + 1,
   candidate status 'placed'; close job when positions_filled = no_of_positions.

Implementation notes
--------------------
1. Seed `statuses` and `hiring_stages` in a seeder BEFORE other seeders; all status_id columns NOT NULL.
2. Validate status_id belongs to the correct module (Form Request / model observer).
3. Do stage/status changes inside a DB transaction together with the history insert.
4. Candidate email is indexed, not unique — decide a duplicate policy (email + phone check on create).
5. Do not store Aadhaar/PAN unless essential; if required, use Laravel encrypted casts.
